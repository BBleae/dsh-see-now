# 切镜头判定的根因与验收边界

这份文档回答三个问题：为什么有些误判反复出现、哪些能靠代码解决、哪些必须在产品上选权衡。

## 信号只有屏幕像素

检测器输入是 64x36 HSV 网格，每帧只回答“这块颜色变了多少”。它没有：

- 物体/人手/商品分割；
- 摄像头元数据、场记、音频事件；
- 场景语义（“这是同一张桌子” vs “这是另一个场景”）。

所以下面几件事不是阈值没调好，而是**同一条观测对应两种解释**。

## 1. 整屏前景停住不离开

候选帧 t：

- 过去：旧场景；
- 当前：整屏被手/产品/包装盖住；
- t+0.5s：还是被盖住。

“整屏前景停住”和“真切到整屏新场景”产生的当前帧+未来帧完全一样。
在固定 0.5s 窗口里，任何只看像素和未来帧的规则都**无法区分**。

能选的路只有：

1. 等更久，等到前景离开；延迟等于前景停留时长，没有上界；
2. 引入分割/语义，判断“这是手/商品”而不是“新场景”；
3. 接受一次误切，不追求零误切；
4. 引入摄像头/音频/操作员事件。

这是信息问题，不是参数量问题。

## 2. 固定外框真切点被误挡

外圈守卫的前提是：

> 外圈没怎么变 + 背景还有一部分稳定 => 这是前景，不是换镜头。

真正切到“外框固定、主体只在中部变”的近景，正好违反这个前提。
它和“前景停在固定外框里”在像素上同样接近，仍然要靠：

- 变化区域是不是从画面边缘进入；
- 是否有连续运动轨迹；
- 语义/分割；
- 或者接受误挡。

只调 border/bg 阈值，会在两类样本之间来回摇摆，不能同时消掉。

## 3. 0.5 秒延迟

未来帧确认的代价就是延迟：

- 窗口缩短：97.5/109.33 这类连续手部会重新变切点；
- 窗口拉长：所有高分真切点延迟增加。

如果产品不能接受延迟，应改成**异步确认**：

1. 候选帧先按“疑似切点”输出，不阻塞画面；
2. 0.5s 后如果被未来帧否定，再撤回/替换这一帧；
3. UI 上表现为“可能闪一下”，而不是“晚 0.5 秒”。

这不是算法免费消除了延迟，而是把延迟换成可撤回的误报。

## 4. 强灯光真切点样本

现有强灯光直播样本都是**连续单机位展示**：

- 键盘盲盒 60s/300s：0 刀；
- 暴雪旗舰店 120s：0 刀；
- 翡翠带货 180s：连续手部，6->2 刀。

它们只能证明“不新增误切”，不能证明强灯光下真切点不被误挡。
makeup-demo.webm 是强光近景演示，但不是直播，不能替代“强灯光直播真剪”。

**验收要求：**

- 至少一段 30 分钟以上、强棚灯、多机位/会切近景的直播；
- 人工逐刀标注，而不是拿检测器输出当 ground truth；
- 分别统计：真切点召回、前景误切、固定外框近景误挡；
- 连续单机位样本不能计入“真切点覆盖”。

## 结论

| 问题 | 能否只靠当前像素解决 | 需要的取舍/新信号 |
|---|---|---|
| 整屏前景停住 | 否，0.5s 内不可区分 | 更长等待 / 分割语义 / 接受误切 |
| 固定外框近景误挡 | 不能同时保召回和零误挡 | 运动轨迹/语义，或接受误挡 |
| 0.5s 延迟 | 不能免费消除 | 异步候选+撤回，或接受延迟 |
| 强灯光真切点 | 是样本问题 | 录 30min 多机位强光直播并人工标注 |
